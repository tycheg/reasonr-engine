## 1. The idea

A system in ReasonR has three interfaces: the web (later mobile, desktop) for people, OpenAPI for integrations, and **MCP** (Model Context Protocol) for AI agents that act **on behalf of a user or a role**: "order a taxi home", "find the orders without a driver and cancel the stuck ones". Everything an agent needs is already in the model: public commands and queries with access, the types of arguments and results, errors, `##` descriptions, texts in the user's language. The engine generates the MCP server from the model, like OpenAPI, and it needs no code.

## 2. Decisions (proposal)

| # | Decision |
|---|---|
| 1 | **The transport is an engine ingress** `ingress: [{ type: mcp, listen: ":8091" }]` or a path `/mcp` on the HTTP ingress (`ingress.http.mcp: true`); the MCP Streamable HTTP protocol. Locally — `reasonrd mcp --stdio` for agents on a developer's machine (test mode, the caller from `--as`) |
| 2 | **Authentication is the same as the API's:** a token in `Authorization` (OAuth 2.1 by the MCP specification: the server is a resource server and serves the metadata `/.well-known/oauth-protected-resource` with the issuer from `auth`); the tenant and the caller come from the token. In test mode — `Test actor=…` |
| 3 | **Tools** are the public commands and queries **available to the caller** (like UI places: the same access computation): `Order.Cancel`, `Order.MyOrders`. The list depends on the caller and their model (a tenant extension) and changes as feature flags roll out: the server sends `notifications/tools/list_changed`. The description is the method's `##` and the text from `texts` in the user's language; the input schema is the JSON Schema of the arguments (as in OpenAPI), the command's target is an `id` parameter |
| 4 | **A tool's result:** a query — `structuredContent` by the JSON Schema of the result and a short text; a command — `accepted` with the notifications to the initiator, or errors with texts (`isError: true`). Pages — the parameters `size`, `cursor` and `next` in the response |
| 5 | **Confirming actions.** Commands are marked with MCP annotations: `readOnlyHint` on queries, `destructiveHint` on commands with `Confirm` in the UI (the command's place is a confirmation) or with `delete`/`forget`; the agent's client asks the user. The model may forbid a command for agents explicitly: `command(customer) Forget() agents no` — **a question to the author** (§4) |
| 6 | **Idempotency:** every command call gets an `Idempotency-Key` from the MCP call's id; a retry by the agent does not run the command twice |
| 7 | **Audit:** calls through MCP are marked in the log and the metrics (`channel=mcp`, the client from `initialize`) |
| 8 | **Tests:** `reasonrd test --driver mcp` — acceptance tests through the MCP tools (like `api`), each step is a `tools/call` by the step's caller; a check that the tool is visible to whoever calls it |
| 9 | **Tools only.** MCP has three kinds of capabilities: tools — actions the agent calls itself; resources — data at an address that the client app or the user attaches to the conversation, like a file; prompts — ready requests the user chooses. Every read of the model is already a query tool (`Order.MyOrders`), so resources would repeat them. We build neither resources nor prompts |

## 3. Example

```json
{ "name": "Order.Cancel",
  "title": "Cancel the order",
  "description": "Canceling an order by the customer, support or an administrator",
  "inputSchema": { "type": "object", "required": ["id", "reason"],
    "properties": { "id": { "type": "string", "format": "uuid" }, "reason": { "type": "string" } } },
  "annotations": { "destructiveHint": true } }
```

## 4. Questions to the author

| Question | Proposal |
|---|---|
| Is MCP for the system's users (an agent on behalf of a customer or staff) or for the model's developers (an agent edits `*.rr`: check, explain, test)? | For the system's users — this is item 5; for developers — item 14.8 "LSP for agents" |
| Does the model need a mark "not available to agents" or "only with confirmation"? | No syntax at first: annotations from the UI (`Confirm`) and the kind of command; add a mark if needed |

## 5. Stages

| Stage | Result |
|---|---|
| **M1. Tools** | The `mcp` ingress (Streamable HTTP), the caller's list of tools, `tools/call` through the executor, errors and notifications, idempotency, `list_changed` |
| **M2. Authentication and tests** | OAuth metadata, `reasonrd mcp --stdio`, `reasonrd test --driver mcp` |
| **M3. The example and documents** | Taxi: an agent orders a taxi and cancels the order (a scenario in the README with MCP Inspector), the RFC, AGENTS.md |

The acceptance criterion:
- the taxi tests pass on `--driver mcp`;
- an MCP client (MCP Inspector) on behalf of a taxi customer sees only their tools and orders a taxi; after the `tips` flag rolls out, `Order.LeaveTip` appears.

## 6. Progress

| Stage | Status | What was done |
|---|---|---|
| M1. Tools | Done | `POST /mcp` (Streamable HTTP, JSON responses) on the HTTP ingress (`ingress.mcp`, always in test mode): `initialize` with `Mcp-Session-Id`, `tools/list` — the public methods whose access the caller can pass, descriptions from `##`, the JSON Schema of input and output (`compiler/apidoc`), annotations; `tools/call` — through the `/api` handlers, errors as `isError`, the retry key is the session and the call id |
| M2. Authentication and tests | Done | Authentication as for the API; `/.well-known/oauth-protected-resource` with the issuers from `auth`; `reasonrd mcp --stdio --as …`; `reasonrd test --driver mcp` — taxi, bank, auth |
| M3. The example and documents | Done | RFC §31.3.2, AGENTS.md, the README |

**Deviations** (for the author's decision):

1. **There is no `notifications/tools/list_changed`** (`listChanged: false`): the server keeps no event stream (GET /mcp is 405); after a flag rolls out the agent rereads the list. A stream — when needed.
2. **`destructiveHint`** — on commands with `forget` or `delete`; the confirmation from the UI (`Confirm`) is not taken into account: the API schema does not know the layout.
3. **A tool's title** is the first line of `##`, not the text from `texts`.
4. **The scenario with MCP Inspector in the README** is a launch command; a live run of the Inspector is manual.
